**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`, which ran `Object.assign(note, changes)` on the stored record. Nothing filtered the keys, so a client could send `id` or `createdAt` and overwrite them. `createdAt` is stored as epoch ms, so `createdAt: 0` became 1970-01-01. POST and PUT were not affected because `validateNoteInput` copies out only `title` and `body`.

**Fix (commit `e9d532a`, with the rest of the PATCH work in `26cc749`):**
- **Validation:** a new `validateNotePatch` in `src/validation.ts` accepts only `title` and `body`, applying the same rules as create. It returns 422 `validation_failed` for any other field, an empty patch, or an invalid value. It rejects unknown fields rather than dropping them silently, so client bugs surface.
- **Store:** `store.patch` in `src/store.ts` now copies only `title` and `body` onto the note instead of using `Object.assign`. Only the validated value reaches the store, so `id` and `createdAt` cannot be changed through PATCH.
- **Server:** the PATCH handler in `src/server.ts` calls `validateNotePatch` and passes the validated value to `store.patch`.

I checked the current `store.ts` and `validation.ts` against that commit and the fix is still in place. I did not run `node --test` for this answer.
