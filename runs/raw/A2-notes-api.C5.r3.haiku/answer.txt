**Root cause:** The PATCH handler passed the raw request body to `store.patch()`, which ran `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, a client sending `createdAt: 0` moved a note's creation date to 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix (commit `e9d532a`):**
- Added `validateNotePatch` in `src/validation.ts`. It accepts only `title` and `body`, using the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. I chose strict rejection over silently ignoring unknown fields, because silent drops hide client bugs.
- `store.patch` now copies only `title` and `body` onto the note instead of assigning the whole object. `id` and `createdAt` can no longer be changed through PATCH.
- Added a regression test in `test/notes.test.ts`.
