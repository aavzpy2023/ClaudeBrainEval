`createStore` no longer crashes on a corrupt `NOTES_FILE`. If the file can't be parsed, it renames it to `<file>.corrupt` and starts with an empty store. All 29 tests pass, including a new one for this case.

The change is in `load()` in `src/store.ts`. I also treat valid JSON that isn't an array as corrupt, since the store couldn't use it either. A later write recreates `<file>` as normal.

The new test in `test/persistence.test.ts` writes `{not json` to a file. It checks that the store starts empty, that the original contents are in `<file>.corrupt`, and that the original path is gone.

If a `<file>.corrupt` already exists from an earlier crash, the rename overwrites it. I didn't add a numbered or timestamped backup name.
