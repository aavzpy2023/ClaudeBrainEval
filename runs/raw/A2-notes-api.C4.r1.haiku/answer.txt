The root cause was that PATCH passed the raw request body straight into `Object.assign` on the stored note, with no filtering. The fix was to accept only `title` and `body` and reject everything else with a 422.

**Root cause:** `PATCH /notes/:id` handed the unvalidated request body to `store.patch()`, which ran `Object.assign(storedNote, changes)`. Any key a client sent was written onto the record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, a client sending `createdAt: 0` produced 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):**
- **`src/validation.ts`:** a new `validateNotePatch` accepts only `title` and `body`, with the same rules as create. It returns 422 for any other field, for an empty patch, or for an invalid value. Strict rejection was chosen over silently ignoring unknown fields, because silent drops hide client bugs.
- **`src/store.ts`:** `patch` now copies only `title` and `body` onto the note instead of assigning the whole object.
- **`src/server.ts`:** the PATCH route uses the new validation.
- **`test/notes.test.ts`:** new tests cover the fix.
