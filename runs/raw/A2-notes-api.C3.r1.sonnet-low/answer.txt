**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`. That function ran `Object.assign(storedNote, changes)`, and nothing filtered or validated the body first. Any key a client sent was written onto the stored record, including `id` and `createdAt`. For example, `createdAt: 0` turned the creation date into 1970-01-01. POST and PUT were not affected, because `validateNoteInput` copies out only `title` and `body`.

**Fix** (commit `e9d532a`):
- **Validation:** a new `validateNotePatch` in `src/validation.ts` accepts only `title` and `body`, with the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. Strict rejection was chosen over silently ignoring unknown fields, because silent drops hide client bugs.
- **Store:** `store.patch` in `src/store.ts` no longer uses `Object.assign`. It now copies only `title` and `body` onto the note, so it protects `id` and `createdAt` even if a caller skips validation.
- **Tests:** `test/notes.test.ts` gained 18 lines of tests for the new behavior.
