`createStore` no longer crashes on a corrupt `NOTES_FILE`. If the file can't be parsed, it renames it to `<file>.corrupt` and starts with an empty store. I added one test for this, and `node --test` passes (29 tests). I haven't committed anything.

- **Fix:** the change is in `load()` in `src/store.ts`. I also treat valid JSON that isn't an array (for example `{}`) as corrupt, since the store couldn't use it either.
- **Rename overwrites:** if a `<file>.corrupt` already exists from an earlier crash, the rename replaces it, so only the most recent corrupt file is kept.
- **Test:** the new test in `test/persistence.test.ts` writes an invalid file. It checks that the store starts empty, that the original bytes are in `.corrupt`, and that new notes persist to a fresh file afterwards.
