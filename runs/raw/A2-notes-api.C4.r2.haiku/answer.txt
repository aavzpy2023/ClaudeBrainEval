**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`, which did `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, a body with `createdAt: 0` turned the note's creation date into 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix** (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):

- **`src/validation.ts`**: added `validateNotePatch`. It accepts only `title` and `body`, with the same rules as create. It returns 422 for any other field, an empty patch, a non-object body, or an invalid value. It rejects unknown fields rather than dropping them, so a client that sends `id` or `createdAt` learns that it had no effect.
- **`src/store.ts`**: `patch` no longer does `Object.assign`. It copies only `title` and `body` when they are defined.
- **`src/server.ts`**: the PATCH route runs the body through `validateNotePatch` and passes only the validated value to `store.patch`.
- **`test/notes.test.ts`**: added tests for the new behavior.

One discrepancy: the project digest lists the PATCH fix as `26cc749`, but the repo's history has it as `e9d532a`. I used the commit in the repo.
