`createStore` no longer throws on a corrupt `NOTES_FILE`. If the file can't be parsed, `load` in `src/store.ts` renames it to `<file>.corrupt` and the store starts empty. The existing 28 tests pass. I didn't add a test for the corrupt-file case or try it by hand.

Valid JSON that isn't an array (for example `{}`) is treated as corrupt too, so it gets the same rename-and-start-empty handling.

If a `<file>.corrupt` already exists, the rename overwrites it, so only the most recent corrupt file is kept. I haven't committed anything.
