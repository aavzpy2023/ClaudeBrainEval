**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`, which did `Object.assign(note, changes)`. Nothing filtered the body. Any key a client sent was written onto the stored record, including `id` and `createdAt`. For example, `createdAt: 0` turned the creation date into 1970-01-01. POST and PUT weren't affected, because `validateNoteInput` copies out only `title` and `body`.

**Fix (commit `e9d532a`):**
- **`src/validation.ts`:** Added `validateNotePatch`. It accepts only `title` and `body`, and applies the same length and type rules as create. It returns 422 for any other field, for an empty patch, or for an invalid value. It rejects unknown fields instead of silently ignoring them, so a client that sends `id` or `createdAt` finds out rather than assuming it worked.
- **`src/server.ts`:** The PATCH handler now runs the body through `validateNotePatch` and passes only the validated value to the store.
- **`src/store.ts`:** `patch()` now assigns `title` and `body` explicitly instead of using `Object.assign`. This guards the store even if a caller skips validation.
- **`test/notes.test.ts`:** Added tests that a PATCH with `id` or `createdAt` returns 422 and leaves the note unchanged. They also cover invalid `title` and `body` values and an empty patch.
