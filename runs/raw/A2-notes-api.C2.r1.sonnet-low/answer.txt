**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`. That function did `Object.assign(note, changes)`, and nothing filtered or validated the body first. Any key a client sent was written onto the stored record, including `id` and `createdAt`. For example, `createdAt: 0` turned the note's date into 1970-01-01. POST and PUT weren't affected, because `validateNoteInput` copies out only `title` and `body`.

**Fix** (commit `e9d532a`):
- **New validator:** `validateNotePatch` in `src/validation.ts` accepts only `title` and `body`, using the same length and type rules as create. It returns 422 for any other field, an empty patch, or an invalid value. Unknown fields are rejected instead of silently ignored, so a client that sends `id` finds out it didn't take effect.
- **Server:** `src/server.ts` runs the body through that validator before calling the store.
- **Store:** `store.patch` in `src/store.ts` now copies only `title` and `body` onto the note instead of assigning blindly. This keeps the store safe even if a caller skips the validator.
