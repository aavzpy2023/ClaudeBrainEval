The root cause was that `store.patch()` copied the request body onto the stored note without filtering it. The fix was to validate the PATCH body and copy only `title` and `body`.

**Root cause:** The PATCH handler passed the raw parsed body straight to `store.patch()` (commit `2da92fb`), which did `Object.assign(note, changes)`. Nothing filtered the keys, so any field a client sent was written onto the stored record, including `id` and `createdAt`. The store keeps `createdAt` as epoch ms, so a client sending `createdAt: 0` would have produced 1970-01-01. POST and PUT were not affected because `validateNoteInput` copies out only `title` and `body` before the store sees the data.

**Fix:** Commit `e9d532a` made three changes:
- **`src/validation.ts`:** Added `validateNotePatch`. It accepts only `title` and `body`, applies the same rules as create, and rejects unknown fields, empty patches, and invalid values.
- **`src/server.ts`:** The PATCH handler calls `validateNotePatch` and returns 422 on failure. It passes only the validated value to the store.
- **`src/store.ts`:** `patch()` now sets `note.title` and `note.body` explicitly instead of using `Object.assign`.

The commit also chose strict rejection with 422 over silently dropping unknown fields, so client bugs surface instead of being hidden. A test was added in `test/notes.test.ts`.
