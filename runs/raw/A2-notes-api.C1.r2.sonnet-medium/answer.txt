**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`. That function ran `Object.assign(note, changes)`, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, sending `createdAt: 0` turned the creation date into 1970-01-01. The only check on the body was that it was a JSON object. POST and PUT were safe because `validateNoteInput` copies out only `title` and `body`.

**Fix (commit `e9d532a`):**
- **New validator:** `validateNotePatch` in `src/validation.ts` accepts only `title` and `body`. It applies the same rules as create (non-empty title, length limits, body must be a string).
- **Rejections:** It returns 422 for any other field, for an empty patch, and for an invalid value. The commit chose rejecting unknown fields over silently ignoring them, because silent drops hide client bugs.
- **Store change:** `store.patch` in `src/store.ts` now copies only `title` and `body` explicitly. This replaces the blanket `Object.assign`, so the store is safe even if a caller skips validation.
- **Tests:** Two new tests in `test/notes.test.ts` cover this. One sends `{id, createdAt, title}` and expects 422 with the note unchanged. The other checks that bad `title` and `body` values and an empty `{}` all return 422.
