**Root cause:** `PATCH /notes/:id` passed the raw request body to `store.patch()`, which did `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, a client sending `createdAt: 0` produced 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix** (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):

- **`src/validation.ts`:** added `validateNotePatch`. It accepts only `title` and `body`, with the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. The commit chose strict rejection over silently dropping unknown fields, so client bugs surface instead of being hidden.
- **`src/server.ts`:** the PATCH handler runs the body through `validateNotePatch` and passes only the validated `result.value` to the store.
- **`src/store.ts`:** `patch` now copies `title` and `body` individually instead of using `Object.assign`, so even a future caller can't overwrite other fields.
- **`test/notes.test.ts`:** added a regression test for the change.
