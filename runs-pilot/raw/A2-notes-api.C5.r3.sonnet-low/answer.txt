**Root cause:** PATCH did an `Object.assign` of the raw request body onto the stored note. Because nothing filtered the body, a client could send `id` or `createdAt` and overwrite them.

**Fix** (commit `26cc749`, shown as `e9d532a` in the current git log):
- `store.patch` now copies only `title` and `body` onto the note.
- PATCH validation is strict, via `validateNotePatch`. Any other field, an empty patch, or an invalid value returns 422. Unknown fields are rejected rather than silently dropped, because silent drops hide client bugs.
