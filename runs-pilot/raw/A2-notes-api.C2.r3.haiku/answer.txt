**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`, which ran `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, sending `createdAt: 0` turned it into 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):**
- **`src/validation.ts`:** a new `validateNotePatch` accepts only `title` and `body`, applying the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. I chose strict rejection over silently dropping unknown fields, so client bugs surface instead of being hidden.
- **`src/store.ts`:** `patch` now copies only `title` and `body` onto the note instead of using `Object.assign`.
- **`src/server.ts`:** the PATCH handler runs `validateNotePatch` on the body and passes only the validated value to `store.patch`.
- **`test/notes.test.ts`:** 18 lines of new tests for this behavior.
