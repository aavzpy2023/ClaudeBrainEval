`createStore` no longer crashes on a corrupt `NOTES_FILE`. If the file can't be parsed, it renames it to `<file>.corrupt` and starts with an empty store. All 29 `node --test` tests pass, including a new one for this case.

I also treat valid JSON that isn't an array (for example `{}`) as corrupt, since the store can't use it. The change is in `load()` in `src/store.ts`. The new test is in `test/persistence.test.ts`.

If a `<file>.corrupt` from an earlier incident already exists, the rename overwrites it.
