`taskq list --limit N` now works with and without `--json`. It shows at most N tasks in insertion order. A value below 1, or one that isn't a number, is a usage error with exit status 2. All 27 tests pass.

The limit is applied in `Repository.list_tasks(limit=None)`, so the SQL stays in `Repository`. The check for values below 1 is in `taskq/cli.py`.

I added two tests in `tests/test_cli.py`: one for plain and JSON output with a limit of 2 over three tasks, and one for `0`, `-1` and `x` exiting with status 2. I didn't commit anything.
