**Root cause:** `PATCH /notes/:id` passed the raw request body straight to `store.patch()`, which ran `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, a client sending `createdAt: 0` would make the note read as 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix** (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):

- **Validation:** added `validateNotePatch` in `src/validation.ts`. It accepts only `title` and `body`, with the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. I chose strict rejection over silently ignoring unknown fields because silent drops hide client bugs.
- **Store:** `store.patch` in `src/store.ts` now copies only `title` and `body` onto the note instead of using `Object.assign`.
- **Tests:** added a case in `test/notes.test.ts`.
