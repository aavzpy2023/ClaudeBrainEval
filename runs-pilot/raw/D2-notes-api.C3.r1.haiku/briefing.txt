[auto] Goal: notes-api, a small REST API for notes using plain `node:http` with zero dependencies. TypeScript runs natively on Node 26 (.ts imports, erasable syntax only). Tests use node:test and node:assert, and `node --test` must pass.

Decisions and why (later ones supersede earlier ones):
- Note ids are `crypto.randomUUID()`, because sequential ids are guessable.
- DELETE is idempotent and returns 204. GET, PUT and PATCH on unknown ids return 404.
- `createdAt` is stored as epoch ms (UTC) and returned as ISO-8601 UTC. `list()` sorts newest first, with insertion order as the tie-break.
- Validation: `title` is required, non-empty, at most 120 UTF-16 units. `body` is optional (default `''`), at most 10000. Invalid content returns 422 `{"error":{"code":"validation_failed",...}}`. Malformed JSON returns 400 `{error:'Invalid JSON'}`.
- **Supersedes the `Object.assign` PATCH:** PATCH accepts only `title` and `body`. Any other field, an empty patch, or an invalid value returns 422 (strict, because silent drops hide client bugs). Root cause of the bug: the raw body was `Object.assign`ed onto the stored note, so `id` and `createdAt` could be overwritten. `store.patch` now copies only those two fields.
- Persistence: if `NOTES_FILE` is set, notes load at startup, or the store starts empty if the file is missing. Every change rewrites the file atomically (temp file `<file>.<pid>.tmp`, then rename).
