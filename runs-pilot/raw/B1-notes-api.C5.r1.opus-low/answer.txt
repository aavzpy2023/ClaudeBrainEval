`createStore` no longer crashes on a corrupt `NOTES_FILE`. When the file can't be parsed, it renames it to `<file>.corrupt` and starts with an empty store. `node --test` passes all 29 tests, including a new one that writes `{not json` and checks three things: the store comes up empty, `<file>.corrupt` holds the original text, and the original file is gone.

The change is in `load()` in `src/store.ts`. Two choices you may want to change:
- **Valid JSON that isn't a list of notes** (e.g. `{}` or `null`) is also treated as corrupt and moved aside.
- **Other read errors** still throw, such as a permission problem. Only a JSON parse failure counts as corruption, so a real I/O problem isn't hidden.

If a `<file>.corrupt` already exists, the rename replaces it, so only the most recent corrupt copy is kept.
