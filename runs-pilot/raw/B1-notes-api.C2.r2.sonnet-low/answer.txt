`createStore` no longer crashes on a corrupt `NOTES_FILE`. If the file can't be parsed, it renames it to `<file>.corrupt` and starts with an empty store. All 29 tests pass, including the new one. I haven't committed anything.

- **Valid JSON that isn't an array:** I treat this as corrupt too, since it can't be loaded as a list of notes.
- **Repeat corruption:** the rename overwrites any earlier `.corrupt` file, so only the most recent bad file is kept.
- **Failed rename:** a failure here (for example, a read-only directory) would still throw at startup. I didn't handle that case.

The change is in `load()` in `src/store.ts`. The new test in `test/persistence.test.ts` writes `{not json`, checks the store starts empty, and checks the original content ends up in `.corrupt`. It then creates a note and checks it reloads.
