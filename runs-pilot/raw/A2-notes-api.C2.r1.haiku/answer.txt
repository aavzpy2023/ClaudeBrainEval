**Root cause:** the PATCH handler passed the raw request body to `store.patch()`, which called `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, a client sending `createdAt: 0` would have turned the note's creation date into 1970-01-01. POST and PUT were safe only because `validateNoteInput` copies out just `title` and `body`.

**Fix (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):**
- **Validation:** a new `validateNotePatch` in `src/validation.ts` accepts only `title` and `body`, using the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. Strict rejection was chosen over silently ignoring unknown fields, because silent drops hide client bugs.
- **Store:** `store.patch` now copies only `title` and `body` field by field instead of using `Object.assign`. The current code in `src/store.ts` (around line 72) does this and then persists.
- **Tests:** `test/notes.test.ts` gained 18 lines of coverage for the new behavior.
