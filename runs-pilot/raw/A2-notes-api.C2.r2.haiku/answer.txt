**Root cause:** `PATCH /notes/:id` passed the raw request body to `store.patch()`, which ran `Object.assign(storedNote, changes)`. Nothing filtered or validated the body, so any key a client sent was written onto the stored record, including `id` and `createdAt`. Because `createdAt` is stored as epoch ms, sending `createdAt: 0` turned the creation date into 1970-01-01. POST and PUT were not affected because `validateNoteInput` copies out only `title` and `body`.

**Fix** (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):

- **`src/validation.ts`:** added `validateNotePatch`. It accepts only `title` and `body`, with the same rules as create. It returns 422 for any other field, an empty patch, or an invalid value. It rejects unknown fields rather than dropping them, so clients find out that their change did not take effect.
- **`src/store.ts`:** `patch` now copies only `title` and `body` onto the note instead of using `Object.assign`. This is a second layer of protection, so the store is safe even if a caller skips validation.
- **`src/server.ts`** routes PATCH bodies through the new validator, and **`test/notes.test.ts`** gained a test for the new behavior.

The memory digest I was given cites different commit hashes (`26cc749` and `7affb30`) for this work. The commit I checked is `e9d532a`, which matches the git log for this repo, so I went with that.
