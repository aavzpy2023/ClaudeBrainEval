**Root cause:** `PATCH /notes/:id` passed the raw request body to `store.patch()`, which ran `Object.assign(note, changes)` on the stored record. Nothing filtered the keys, so a client could send `id` or `createdAt` and overwrite them. Because `createdAt` is stored as epoch ms, sending `createdAt: 0` would make the note read as 1970-01-01. POST and PUT were not affected because `validateNoteInput` copies out only `title` and `body`.

**Fix** (commit `e9d532a`, "Fix PATCH overwriting id and createdAt; reject unknown fields with 422"):

- **`src/validation.ts`:** added `validateNotePatch`. It accepts only `title` and `body`, applies the same rules as create, and returns a 422 `validation_failed` error for unknown fields, an empty patch, or an invalid value. It rejects unknown fields instead of dropping them silently, so client bugs show up immediately.
- **`src/store.ts`:** `patch` now copies only `title` and `body` onto the stored note instead of calling `Object.assign`.
- **`src/server.ts`:** the PATCH handler runs the body through `validateNotePatch` and passes only the validated value to the store.
- **`test/notes.test.ts`:** added tests for the new behavior.
