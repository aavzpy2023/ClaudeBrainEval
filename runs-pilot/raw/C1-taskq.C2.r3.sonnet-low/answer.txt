`taskq list --limit N` now works with and without `--json`. It shows at most N tasks in insertion order. A value below 1, or one that isn't an integer, is a usage error with exit status 2. The two new tests pass along with the rest of the suite (27 tests).

- **`taskq/cli.py`:** `--limit` is validated by a small `_positive_int` check, so the error comes from argparse.
- **`taskq/repository.py`:** `Repository.list_tasks(limit=None)` applies the limit in the SQL query, which keeps the SQL inside `Repository` as before.
- **`tests/test_cli.py`:** one test covers plain and `--json` output with a limit. The other covers `0`, `-1` and `x`, all exiting with 2.

I haven't committed anything.
